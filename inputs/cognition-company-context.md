## Competitors / alternatives (starting hypothesis — not fixed)

## Candidate buyer segments / ICPs
1. **Self-serve / power developers** — Pro/Max; avoid context-switching; come back to a tested PR; DeepWiki for unfamiliar repos.  
2. **Engineering / platform leads** — Teams; backlog parallelism (migrations, tests, security, tech debt); merge rate, review burden, cost per merged PR.  
3. **Enterprise buyers (VP Eng / CIO / platform / security / procurement)** — governed fleets, SSO/audit/isolation/VPC, measurable modernization ROI.  
Secondary: designers/PMs/founders shipping with agents (weaker core ICP; Replit often wins blank-page).

## Seeded buyer-language / trust themes (public research 2026-09-15)
Conversation shifted from “AI replaces developers” → **“delegate bounded work, then inspect the receipt.”** Credible Devin frame: senior-level codebase understanding + junior parallel execution — **not** autonomous senior judgment. Objections: unpredictable task success; merged PR ≠ good PR; interactive tools feel safer to steer; cost predictability; need diffs/CI/recordings/review time. Avoid replacement rhetoric. Prefer proof over vibes.

## Starting message territories (for creative tests)
1. Give engineers their context back (ticket → tested PR)  
2. Backlog is a parallelism problem (one playbook / many repos)  
3. Don’t trust the demo — inspect the proof (diff, CI, recording)  
4. Modernization with measurable economics (enterprise)  
5. Understand the repo before changing it (DeepWiki → PR)  
Optional product demo: Desktop command center (Claude + Codex + Devin). Prefer **Sign up / Start free** CTA tests vs comment-only.
